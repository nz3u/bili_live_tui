# BILILIVE_TUI
一个用于黑听B站直播的tui客户端
![示例图](./img/bililive1.png)

# 功能
- 查看弹幕、发送弹幕
- 友好的登录方式
- 彩色弹幕显示
- 自适应终端大小

# 如何使用
## 配置文件
可在直播间界面按 **F2** 打开设置面板，修改默认房间、房间列表、快捷键、缓存条数、全部显示选项和 User-Agent，也可手工编辑 `config.toml`。
```toml
room_id = 7777 # 默认直播间：启动时优先使用；省略时使用列表首项
room_ids = [7777, 1, 2] # 可选：按此顺序切房；默认房间不在列表时自动加入循环
room_switch_key = "ctrl+n" # 可选；F6 始终可切房
settings_key = "f2" # 可选；F2 始终可打开设置
chat_buffer = 200 # 缓存弹幕条数，范围 1–100000
show_room_title = true
show_room_number = true
color_mode = true
show_ship_level = true
show_medal_name = true
show_medal_level = true
user_agent = "" # 留空使用内置浏览器标识；不能包含控制字符
```
快捷键支持 `ctrl+a`–`ctrl+z` 或 `f1`–`f12`，但退出、Tab/Enter/退格及保存等保留键、F2/F6 冲突会被拒绝。房间 ID 必须为正整数，列表不能重复相同 ID。旧配置若同时设置了 `room_id` 与 `room_ids`，请确认 `room_id` 是希望启动时进入的默认房间。

## 启动软件
### `linux`或`macos`
直接打开二进制文件即可
### `windows`
直接双击或运行 `bililive.exe` 即可，无需任何启动脚本。程序启动时会自行：
1. 把控制台**输出**代码页切换为 UTF-8（保证中文不是乱码）；
2. 必要时**重启自己一次**，使字符宽度表与 Windows 控制台实际绘制宽度一致。

第 2 点是二维码能否扫出来的关键。`go-runewidth` 在包 `init()` 里就按当时的控制台代码页决定“东亚字符宽度”，而 `init()` 跑在 `main()` **之前**。代码页为 936 时，它把制表线 `─│╭`、方块 `█▀▄` 判为 2 格，控制台实际却只画 1 格，于是 lipgloss 按错误宽度排版，边框错位、二维码被削边而扫不出来。

之前的 `start.bat` 之所以正常，是因为它在**启动进程之前**就把代码页设成了 65001，`init()` 看到的已经是 UTF-8。直接双击 exe 时没有这一步，而代码页一旦在 `init()` 被读取，`main()` 里再改就来不及了。所以程序现在内置了这一行为：检测到代码页不是 65001 时，先切到 UTF-8，再用同一个 exe 重启一次（用环境变量防止无限重启），重启后的进程 `init()` 看到的就是 65001，与 `start.bat` 完全同一条路径。控制台只有一个窗口，输入输出原样继承。

（输入代码页保持不动：Bubble Tea 按键解码走系统 ANSI 代码页，强行改成 UTF-8 反而会让中文输入乱码。）

可用 `BILI_TUI_NO_UTF8_RELAUNCH=1` 关闭自动重启（例如 stdout 被重定向到文件时，程序本来也不会重启）。

## 登录
直接扫描二维码即可。
由于在部分终端下，二维码无法正常显示，所以同时将二维码保存为文件`login.png`,扫描该文件也可完成登录。`login.png` 保存在**可执行文件所在目录**（启动时会在界面上显示完整路径），不再受启动目录影响。

## 操作方式
- **Enter**：在弹幕区进入输入；在输入区发送弹幕。失败自动把草稿放回输入框，重复发送被抑制。
- **Tab / Shift+Tab**：切换弹幕区和输入区；**Esc**：返回弹幕区，保留草稿。
- **Alt+F**：在浏览器打开当前直播间网页 `https://live.bilibili.com/<房间号>`（优先短号）。
- 弹幕区支持方向键、Vim 风格按键及鼠标滚轮；在底部时自动跟随新弹幕，向上滚动后停留阅读。
- **Ctrl+N / F6**（或自定义切房键）：两个区域都可切房；只有一个房间时提示到设置添加列表。切房期间保留草稿，不向即将离开的房间提交新提交。
- **F2**（或自定义设置键）：打开/关闭设置；**Ctrl+C** 始终退出。
- 发送成功或失败都会在弹幕输入框内提示 1 秒（成功提示“发送成功”，失败提示原因并把失败内容放回输入框）；提示只是输入框里的文字，不会清空、替换或抢走你的输入，输入永远优先。

### 设置面板
- **Tab / Shift+Tab / 上下箭头** 选择字段或按钮，文本直接编辑；布尔选项用 **Enter / 空格 / 左右箭头** 切换。
- **Ctrl+S** 或“保存”保存配置；显示、缓存、快捷键及 User-Agent 即时应用。普通保存不会切房，也不会中断弹幕收发；默认房间用于下次启动。
- “保存并进入默认房间”保存后立即切到默认房间；切房失败仍保留原房间并显示错误。
- **Esc / F2** 或“取消”放弃未保存修改并恢复原焦点及草稿。保存期间暂不允许关闭面板，但 Ctrl+C 仍可退出。
- 保存会校验输入、在替换前检查外部修改，并使用临时文件写入后替换原文件。原文件完整保留为 `config.toml.bak`（每次保存更新为上一版）；未知 TOML 配置按语义保留，注释会重排，原注释可在备份找回。不要在面板保存时同时用其他编辑器修改配置；冲突时关闭并重开设置读取最新内容。
- 面板随终端缩放重新布局，选中字段保持可见；极小窗口显示扩大窗口的提示。

## 弹幕发送与断线恢复
- 输入长度使用当前账号在该房间的弹幕长度权限（无法取得时默认 20 字）。
- 发送结果在弹幕输入框内提示 1 秒：成功显示“发送成功”，网络或接口失败显示原因并把失败内容放回输入框；未登录时明确提示不会发送。提示不会覆盖你正在输入的内容。
- 发送成功仅表示发送接口返回成功，不保证平台最终广播；接口额外提示也会显示并保留草稿。
- 弹幕连接断开或长时间无数据时自动重连，临时失败会持续退避重试；重连不会终止界面订阅。
- 切房失败保留原房间；切房和退出会取消旧房间相关请求。断线期间错过的弹幕不会自动补收。

## 开发验证
回归测试使用本地模拟 HTTP/TCP 服务，不需要登录，也不会向真实直播间发送弹幕；包含原始键盘输入、缩放/切房/发送/设置保存组合测试。Windows 另在隔离的隐藏控制台中运行两个程序，验证按键、中文输入、退出后控制台模式恢复以及输出代码页切换为 UTF-8，并单独验证“在 936 控制台上启动会重启到 UTF-8 控制台、且方块字符宽度为 1 格”（回归“exe 可直接运行、不再需要 start.bat”），不向用户当前终端注入按键：
```shell
go test ./... -count=1 -timeout=60s
go vet ./...
```
